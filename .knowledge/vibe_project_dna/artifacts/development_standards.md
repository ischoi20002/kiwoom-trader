# 📐 Vibe 프로젝트 개발 및 디자인 표준 (Standards)

본 문서는 Vibe 프로젝트의 코드 무결성과 UI 일관성을 유지하기 위한 절대 규칙을 정의합니다. 안티그래비티는 모든 수정 작업 시 이 표준을 최우선으로 준수해야 합니다.

## 1. 리포트 디자인 황금률 (The Golden Layout)

### 🚨 [중요] 사이드바 및 본문 구조
`trade_report.py` 등 결과 리포트 생성 시 아래의 구조를 절대 변경하지 마라:
- **Body**: `display: flex`를 바디 레벨에서 제거하고 기본 블록 구조를 사용하라. (브라우저 간 호환성 최우선)
- **Sidebar**: `position: fixed`를 사용하여 화면 좌측에 고정하라. 너비는 `280px`를 준수한다.
- **Main Content**: `margin-left: 310px` (280px + 30px 여백)를 주어 물리적 거리를 확보하라.
- **Width**: 본문 영역은 `width: auto`로 두어 가로 방향으로 찌부러지는 현상을 원천 차단하라.

### 🚨 HTML/CSS 무결성
- **상호 배타적 간격**: 사이드바와 본문 사이에는 최소 20~30px의 안전 마진을 두어 어떤 차트도 가려지지 않게 하라.
- **태그 닫기 누락 금지**: 파이썬 f-string으로 HTML을 생성할 때, 닫히지 않은 `</div>`가 리포트 전체 레이아웃을 붕괴시키는 일이 없도록 전수 조사하라.

## 2. 코드 구현 원칙 (Coding Standards)

### ✅ 중복 논리(Redundancy) 배제
- 동일한 수식(RSI, MACD, MA 등)을 여러 파일에 분산 구현하지 마라.
- **공통 분모**: 지표 계산은 반드시 `strategy_selector.py`의 `calculate_technical_indicators` 또는 `signals.py`의 공용 함수를 호출하여 일관성을 유지하라.

### ✅ 리포트 데이터 출력 
- **거절 신호 기록**: Smart Buy 필터에 의해 거절된 신호는 반드시 리포트의 `Smart Metrics` 섹션에 수치로 표시하여 사용자에게 '왜 진입하지 않았는지'에 대한 근거를 제공하라.
- **날짜 정렬**: 모든 매매 일지는 시간순(Ascending)으로 정렬하여 리포트 상의 흐름이 깨지지 않게 하라.

## 3. 서비스 지향 상태 관리 (State Management)

### 🚨 [중요] 상태 변수 선언 금지
- **GUI 클래스**: `k_trader_gui.py` 및 `ui/tabs/` 내의 클래스에서 `self.positions`, `self.history`와 같은 상태 변수를 직접 선언하지 마라.
- **접근 방식**: 모든 상태 정보는 `self.app.portfolio`를 통해서만 접근하며, UI는 이를 관찰하여 '표시'만 하는 역할로 한정한다.
- **동기화**: 상태 변경 로직은 오직 `PortfolioManager` 내부에서만 수행되어야 하며, UI는 `gui_callback`을 통해 변경 사실을 전달받아야 한다.

## 4. 데이터 수집 및 동기화 전략 (DB-First)

모든 엔진(실시간 감시, 백테스트, 종목 선정)은 데이터 수집 시 아래의 **'로컬 우선(Local-First)'** 원칙을 절대적으로 준수해야 합니다.

### 🚨 엔진별 데이터 전략 세분화 (Engine-Specific Policies)

각 엔진의 목적에 따라 데이터 유효성 기준을 아래와 같이 엄격히 분리하여 적용한다.

1.  **실시간 감시 엔진 (Monitoring)**
    *   **기준**: **20분 내 최신성 (Recency)**
    *   **전략**: 앱 기동 속도 최우선. 20분 이내 데이터가 있다면 즉시 시작하고 부족한 분량만 배경 스레드에서 동기화하라.
2.  **종목 선정 엔진 (Selection)**
    *   **기준**: **최종 거래일 데이터 포함 여부 (Latest Closings)**
    *   **전략**: 오늘 장이 끝난 후라면 오늘의 일봉/분봉 데이터가 반드시 존재해야 한다. 20분 단위가 아니라 '오늘 데이터의 유무'가 핵심이며, 부족 시 선정 프로세스 진입 전 API 보충을 완료하라.
3.  **백테스트 엔진 (Backtesting - Pure Offline)**
    *   **기준**: **하베스팅 데이터 기반 100% 완결성**
    *   **전략**: 백테스트 구동 중 API 호출을 절대 금지한다. 공백은 '거래 정지(Halt)'로 간주하여 직전 종가 유지 및 거래량 0으로 처리하라. 데이터 부족 시에는 하베스트 서비스를 통해 먼저 DB를 보충해야 한다.

## 5. 안티그래비티 자가 점검표 (Checklist)
1.  새로운 도표를 리포트에 추가했는가? -> 기존의 고정 사이드바 마진 구조를 유지했는가?
2.  수익률 계산식을 수정했는가? -> 다른 모듈의 계산식과 결과가 일치하는가?
3.  데이터를 새로 가져오는가? -> **해당 엔진의 특화된 최신성/완결성 기준을 따랐는가?**
4.  디자인 요소를 변경했는가? -> **"가독성이 가장 중요하다"**는 사용자님의 0순위 가치를 훼손하지 않았는가?
